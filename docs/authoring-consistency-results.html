Implemented behavior

  • Notes: comment-only lines, including empty lines inside multiline notes, do not end dialogue or action paragraphs. Actual blank lines outside notes still separate them. Leading notes may precede title frontmatter. Inline concatenation, first-close behavior, unclosed-note handling and physical source line indexes remain compatible.
  • Outline: a section belongs to its nearest shallower ancestor; a scene belongs to the innermost current section. Scenes preceding sections remain roots, and skipped depths do not create artificial headings. Existing block ranges and folding semantics are retained.
  • Highlighting: structural content permits same-line comment scopes, while multiline notes retain comment state without trapping later visible lines inside the preceding structure. Tests use the actual TextMate and Oniguruma engines.

README and changelog document the behavior. The two tokenizer dependencies are exact-pinned development tools; they are excluded from the extension bundle and VSIX.

A complete short-screenplay workflow

The fixture Last Light follows Ada and Leo restoring a failed projector so one audience member can see the ending. It has three scenes, nested sections, an existing alphanumeric scene ID, production tags, inline notes and a multiline delivery note containing a blank line.

  1. Open the fixture and number missing scenes while preserving #2A#; a second numbering run makes no change.
  2. Revise “Every frame.” to “Every single frame.” through the actual typing command, then insert a hidden delivery note between ADA’s cue and speech. Assert the exact source fragment landed before proceeding.
  3. Query the actual document-symbol provider and assert the complete nested hierarchy. Open the preview and verify revised render-message content separately.
  4. Export Fountain and PDF through extension commands. Assert title, speech order and revised dialogue, while excluding the hidden notes. Extract text from the actual PDF.
  5. Generate breakdown Markdown/CSV and a shooting schedule. Assert three scenes, speaking cast, production tags and the existing scene identifier.

Observed friction: The automated typing harness initially sent an entire comment as one typing event; VS Code added another closing delimiter. Sending individual keystrokes correctly overtypes the auto-inserted closer and passes the exact-source assertion. No unresolved authoring issue was found in this fixture. This is an automated workflow fixture, not a claim of human user testing.

Review corrections and lessons

  • Multiline notes: comparing raw versus stripped text is insufficient because empty lines inside a note must also be invisible. Preserve comment coverage by source line.
  • Grammar scope recovery: a multiline child comment can prolong its parent structure. Release the structural context before the root comment takes ownership, then verify the following visible scopes using carried tokenizer state.
  • Editor action coverage: checking downstream exports alone would not prove the hidden note was actually inserted. The host now asserts the exact revised source fragment.
  • Preview evidence: a tab title proves which document is open, not rendered body content. The mock test asserts the revised posted message and absence of stale text and comments.
  • Typing fidelity: send character events when verifying auto-closing behavior; a bulk type event does not represent the same editor interaction.
  • Harness expectation: preview tab names use the filename, not title frontmatter. The test was corrected to match existing product behavior.
