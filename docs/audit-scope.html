ScreenMark audit scope

Requested 5 September 2026. Deliverable: a comprehensive, self-contained HTML audit in docs/audit.html. This is an assessment; source fixes and release operations are outside the requested scope.

Review plan

  1. Record and hash every file present outside internal Git metadata. Separate first-party files, generated artifacts, packaged content, and installed dependencies.
  2. Use parallel Astra agents for core data logic, PDF/HTML/preview, and VS Code integration; inspect build, dependency, documentation and visual assets centrally.
  3. Run the existing tests, type check, build, focused defect reproductions, PDF inspection and package comparisons. Distinguish confirmed failures from risks and environmental limits.
  4. Consolidate findings by impact, document architectural tradeoffs and strengths, and include every inventoried file with its actual review depth. Independently verify report coverage.

Evidence standard

Each actionable finding names its location, trigger, observed impact and smallest appropriate remediation. Third-party code receives inventory/dependency analysis, not a claim of manual line-by-line review. Git metadata is excluded. No commits, pushes or deployments.
