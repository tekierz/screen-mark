1 · Comment-only lines do not separate dialogue

A hidden note must not change the surrounding screenplay structure. Only an actual blank or whitespace-only line outside a comment ends a dialogue or action paragraph.

Retain dialogue through the note

**MAYA**
<!-- delivery note -->
> Hello.

One MAYA dialogue containing “Hello.” The note contributes no printed rows or orphan action.

Keep intentional separation

**MAYA**
<!-- delivery note -->

> Hello.

The authored blank line still ends dialogue. The existing orphan-blockquote fallback remains intact.

  • Skip comment-only source lines without flushing a pending dialogue or action paragraph. This includes whitespace around notes, adjacent notes, and blank lines inside a multiline note.
  • Preserve real blank separators before or after a note. Keep original zero-based source line numbers under LF and CRLF.
  • Retain existing inline concatenation: Before<!-- note -->after becomes Beforeafter. Visible content on different physical lines keeps its newline.
  • Keep existing first-closing-delimiter behavior for nested-looking notes. An unclosed comment continues to EOF.
  • Action lines separated only by a note form one action paragraph. Parentheticals and lyrics after notes remain attached to the active dialogue.
  • Skip leading comment-only lines when finding opening frontmatter. A genuine leading blank still prevents frontmatter recognition. Comments inside frontmatter remain invisible.

Implementation boundary: retain comment-span line information while removing notes, then distinguish an emptied comment line from an authored separator. Keep the public stripNotes(text): string behavior compatible. The AST does not gain comment nodes, and scene numbering continues to use its own original UTF-16 offset mask.

Primary files: src/core/parser.ts; test/parser.test.ts; related export/editor regressions; README.md.

2 · Sections contain their subsections and scenes

Build the document-symbol hierarchy using a small stack of section ancestors. A section attaches to the nearest preceding section with a shallower depth. A scene attaches to the current innermost section; scenes before any section remain at the root.

  Opening scene
  Sequence A
    Scene 1A
    Deep Beat
      Scene 2
  Sequence B
    Scene 3
Act Two
  Scene 4
  • A same-depth or shallower section closes the relevant ancestors. Skipped levels do not create synthetic headings.
  • ## remains reserved for scenes. Section nesting uses the parser’s existing depths 1 and 3–6.
  • Keep existing names, scene IDs, symbol kinds, selection ranges and block-end calculation. Folding already follows section depth; verify that symbol containment agrees with it.
  • Assert exact hierarchy and ranges for pre-section scenes, deep nesting, siblings, shallow resets, skipped depths and single-line blocks.

Primary files: src/features/symbols.ts; editor provider regressions; real extension-host smoke.

3 · Inline notes receive comment scopes

The grammar must let <!-- … --> participate in tokenization within structural lines, rather than letting a whole-line match swallow the note.

  • Cover scenes and scene IDs, sections, character cues including dual markers, parentheticals, centered text, dialogue, lyrics, transitions and frontmatter values. Preserve useful scopes for visible markers and content.
  • Test notes before, within and after content on representative structural lines. Include multiple notes, delimiter-like text inside notes, empty notes and indentation.
  • Test state across lines: multiline and unclosed comments stay comments; subsequent visible lines recover their normal scopes after closure. A note must not leave the following scene or dialogue trapped in the preceding structural scope.
  • Use the actual TextMate tokenizer with Oniguruma, carrying its rule stack across each fixture. Assertions check the scopes at relevant UTF-16 positions, not theme-specific colors or a second regex recognizer.

Add exact-pinned development dependencies vscode-textmate@9.3.2 and vscode-oniguruma@2.0.1, verified from their registry metadata during this check-in. The existing Bun test runner is sufficient. These dependencies are test-only and remain outside the extension bundle.

Primary files: syntaxes/screenmark.tmLanguage.json; new test/grammar.test.ts; package.json; bun.lock. The official TextMate library documents the registry/tokenization API and VS Code’s Oniguruma bindings provide the regex engine. Use the editor’s scope inspector for a visual cross-check.
