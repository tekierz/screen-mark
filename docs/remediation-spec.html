Approved implementation decisions

Financial input is strict

Blank amount cells remain allowed. Invalid nonempty amounts, sub-cent values and unsafe magnitudes stop Budget Summary with a source-located error and leave the document untouched. Arithmetic uses integer cents internally.

PDF glyph failures are explicit

Keep the current Courier fonts and their Western European character coverage. Unsupported rendered characters, empty printable output and title metadata that cannot fit produce clear errors before any output file is written.

Scene estimates are conservative

Measure retained rows in the complete paginated screenplay, then round each scene up to an eighth. The sum is a scheduling estimate and may exceed physical page count, especially for many short scenes.

Produce a local 0.3.1 candidate

Use Bun throughout, pin the packager, bundle PDFKit with its runtime data and notices, and test the packaged artifact in an isolated editor profile. The deliverable is a verified local VSIX and an HTML completion report.

1 / Preserve data

Owned totals, correct tables and exact cents

Generated-region ownership

A Totals heading alone does not grant replacement ownership. A generated block must have the existing ScreenMark generated marker immediately beneath its heading, followed by the recognizable Section / Estimate / Actual / Variance table. Parsing and replacement will share one bounded region scanner.

  • Scan only the generated table, stopping at its final generated Total row when present. A closing marker is valid only at that local boundary; never search across notes or later sections for a distant sentinel.
  • Support legacy marker-plus-table blocks without a closing marker by adding one at the table boundary. Do not absorb an adjacent second table, unexpected heading, producer prose or malformed-width row. Ambiguous malformed generated blocks fail before editing.
  • Preserve unowned Totals headings and their content. Valid source budget tables beneath them participate in totals; only positively identified generated ranges are excluded from ingestion.
  • Refresh multiple independently owned blocks in place to the same result. Preserve all intervening content; do not delete duplicate blocks automatically.
  • Preserve untouched bytes and newline style. Reset parser section/table state when skipping generated ranges. Every successful refresh must be exactly idempotent.

Table and amount handling

Replace raw pipe splitting with a small scanner that respects escaped pipes and odd/even backslash runs. Validate data-row width against its recognized header and reset header state when a table ends. A row such as | Camera \| lens | 100 | 120 | kit | must preserve the item and both amount columns.

Accept ordinary decimal dollar amounts, negative values, optional dollar symbols, correctly grouped thousands separators, and at most two decimal places. Reject nonempty invalid values such as 0x10, 1e3, $, 1,23, 1 2 and 0.001. Errors identify the line, section and column. Check arithmetic and variance for overflow.

Retain existing numeric-dollar result interfaces and display style, while parsing and summing integer cents internally. Normalize public numeric inputs through a safe cent round-trip so valid values such as 0.29 work. Equal-cent totals produce an em dash, never “$0 under.”

Primary files: src/core/budget.ts; test/budget.test.ts; budget error handling in src/extension.ts and the editor regression suite.

Acceptance: duplicate/unowned headings, distant sentinels, legacy blocks, trailing notes, adjacent tables, escaped cells, CRLF and repeated refreshes preserve input data. Invalid input applies zero editor edits. Estimates 0.10 + 0.20 and actual 0.30 compare equal.
2 / Preserve screenplay output

Bounded rendering and semantic export

PDF layout

  • Wrap all text-bearing elements to explicit widths: scene headings and IDs, normal/dual cues, dialogue, parentheticals, action, lyrics, transitions, centered text, continuation cues and title fields. Keep the existing 12-point Courier geometry and reserve separate scene-number gutters.
  • Skip structural sections before inserting layout spacing. They add no rows and cannot erase a preceding explicit page break.
  • Compute transitive keep groups so a scene remains with its first printable content. A dialogue whose complete keep group fits on a body page moves as a whole; longer dialogue splits with paired continuation markers and retained speech on both sides. If a scene heading plus an otherwise page-sized dialogue cannot fit together, split the dialogue to preserve the scene with its first speech.
  • Count wrapped continuation cues in page capacity. Oversized dual dialogue repeats the relevant cues on continuation pages and retains every body row exactly once. No page exceeds the 54-row body limit.
  • Give title, author/credit and footer fields bounded regions. Reject metadata that cannot fit the title page rather than clipping it or shrinking type.

Character and empty-output contract

Preflight the strings actually rendered, including intentional uppercasing. Support printable ASCII, supported Latin-1 characters and the existing PDFKit WinAnsi punctuation mapping, including curly quotes, en/em dashes and the euro sign. Layout whitespace is handled separately; unsupported control characters and glyphs are errors.

An unsupported character error reports its code point and source line or title field. No lossy replacement or silent transliteration occurs. Empty, comments-only, outline-only and breaks-only documents fail as having no printable content. A title-only document remains a valid one-page export. Existing output files remain untouched on rejection.

Fountain semantics

Use explicit Fountain forcing for action paragraphs and character cues so ScreenMark’s parsed types survive import, including numeric and non-Roman names. Preserve genuine scenes, sections, transitions, lyrics, centered elements, page breaks and dual dialogue. Verify literal control/inline-marker collisions with an independent importer; if text or an identifier cannot be represented faithfully, return a source-located error instead of silently changing it.

Add one exact-pinned, development-only Fountain parser for semantic test assertions; the candidate is fountain-js. Check exported tokens and visible text against the Fountain syntax reference, rather than writing a second recognizer that repeats the serializer’s assumptions.

Primary files: src/core/pdf.ts; src/core/fountain.ts; test/pdf.test.ts; test/fountain.test.ts. PDF rows gain optional source scene metadata for workstream 4; the screenplay AST stays small.

Acceptance: extracted supported text survives; rendered long-field/boundary fixtures have no clipping or orphans; empty/unsupported exports fail before writes; page breaks after sections survive; long single/dual dialogue retains all content; independent Fountain import retains intended types and text. Replace the misleading short-dialogue fixture with exactly counted rows.
3 / Fix editor state and edits

Current-document state and safe edit ranges

  • Preview: cancel pending debounce work on immediate document switches and disposal; reject stale callbacks. Keep the existing single HTML shell, ready handshake and latest-render cache. Edit A → switch B → timeout → edit B must remain on B.
  • Scene numbering: obtain eligible scenes and existing IDs from parser elements. Insert after the last visible heading character outside comments, preserving original UTF-16 code-unit offsets and CRLF. Frontmatter and comment contents stay unchanged; existing IDs remain intact.
  • Budget destination: use the active document’s workspace root. Use the sole root when unambiguous; otherwise show the editor’s folder picker. Cancellation creates nothing. Only a FileNotFound error permits workbook creation; other filesystem failures do not trigger an overwrite attempt.
  • Completions: align filter text with marker-inclusive prefixes and consume an existing closing character marker in the replacement range. Accepting at **MA|** must yield one complete MAYA cue and dialogue starter with no stray suffix.
  • Errors: perform core validation inside command error handling and before writes/edits. Observe failed edits and failed external PDF opening. Keep validation rules in core and notifications in the editor adapter.

Real host verification

Add a small async extension-host runner using the existing esbuild, VS Code API and Node assertions. Launch the installed editor with unique temporary user-data, extensions and two-root workspace directories. Keep synchronization, updates and third-party extensions out of this fixture profile.

Exercise actual typing with auto-closing enabled, trigger and accept suggestions, number commented scenes, switch preview documents before the debounce expires, and create/refresh the second root’s budget. Observe the real preview tab title and complement it with mock assertions on rendered message bodies; the public VS Code API does not expose webview DOM contents.

Primary files: src/extension.ts; src/features/preview.ts; src/features/completions.ts; new test/editor.test.ts; test/extension-host/smoke.ts; one small host launcher under scripts/.

Acceptance: targeted mocks and a real isolated host run both pass. The real suggest widget accepts marker-prefixed completions with automatic closing enabled. Rapid switching stays on the active screenplay. A second numbering invocation makes no changes, including for headings/comments containing emoji.
4 / Define planning contracts

Safe reports and explicitly measured eighths

Initialize production tag arrays using own-property checks so @constructor: crane is a safe ordinary category. Keep the existing plain-object shape and category syntax.

Add one small escapeMarkdownCell helper shared by budget, breakdown and schedule tables. Escape backslashes and pipes and normalize embedded line breaks; apply intentional Markdown styling after escaping content. Preserve machine-facing CSV field names while labeling human-facing cast columns “Speaking cast.” Explain that only dialogue cues contribute names and silent performers are not inferred.

Occupied-eighths definition

  1. Lay out and paginate the complete screenplay once using the corrected PDF engine.
  2. Attribute retained body rows to their source scene. The following scene owns interscene spacing; continuation rows inherit their dialogue’s scene.
  3. Count content and retained spacing/continuation rows. Exclude the title page, pre-scene material, control markers, discarded leading blanks and unused page tails.
  4. Compute each scene as max(1, ceil(occupiedRows × 8 / 54)). Total eighths is the sum of scene estimates used by scheduling.

Seven occupied rows therefore require two eighths; fifty-four require eight. Rounding up each scene is conservative and can substantially inflate a script containing many short scenes. Reports will explicitly distinguish these estimates from physical PDF page count. The existing location and exact day/night ordering remains a draft scheduling heuristic.

Primary files: src/core/markdown.ts (new); src/core/breakdown.ts; src/core/schedule.ts; shared PDF scene-row metadata; test/breakdown.test.ts; README.md; regenerated sample reports.

Acceptance: adversarial tag keys do not throw; delimiter-rich fields keep the expected table columns; every retained scene row has one owner; eighths match the declared full-layout formula; explicit breaks do not charge unused tails; schedule totals use those same eighths.
5 / Verify a coherent release

A pinned Bun workflow and an artifact-based smoke test

  • Make Bun the documented package manager and use one committed bun.lock; migrate away from the stale package-lock rather than maintaining two competing lockfiles. Pin a Bun version through package metadata and pin the packager to a verified exact version. The locally inspected candidate is @vscode/vsce@3.9.2.
  • Run typecheck, focused/full tests and build through a single verified package entry point. Replace npm debug tasks with an explicit Bun build task. Remove the packager’s npm-based prepublish hook and invoke verification directly from the Bun release command.
  • Bundle PDFKit’s runtime graph with the extension, copy its required data directory alongside the bundle, and ship bundled third-party license notices. Package with dependency discovery disabled, so vsce does not invoke npm or enumerate node_modules.
  • Exclude source tests/tooling, dependency fixtures/browser copies, local workbooks, source maps, lockfiles and audit/specification reports from the VSIX. Keep intended source/generated samples, required runtime data, icon/grammar/snippets and license notices.
  • Disable automatic issue-link rewriting in packaged README examples. Check code examples after packaging, while retaining valid image and documentation links.
  • Prepare version 0.3.1 consistently across package metadata, lock metadata, changelog, installation instructions and artifact name. Regenerate the sample PDF and planning outputs from current source; remove stale author/navigation/page/cast claims.
  • Install the fresh VSIX into a disposable extensions directory and run the host smoke against that installed artifact. Assert its loaded extension path and runtime assets belong to the package, not the source workspace.

The package command must fail on a failed check. A mock-only pass cannot satisfy the real-host gate. A separate HTML completion report will record test counts, editor version, PDF inspection, archive contents, remaining limits and the final artifact path.

Primary files: package.json; bun.lock; esbuild.js; .vscodeignore; .vscode/launch.json; .vscode/tasks.json (new); lean scripts/ verification helpers; README.md; CHANGELOG.md; generated sample/artifact outputs; docs/remediation-results.html.

Acceptance: fresh local VSIX passes isolated installed-artifact smoke; code examples are intact; runtime assets/notices are present; unused dependency fixtures and audit docs are absent; versions and packaged docs agree. The release command uses Bun without hidden npm/yarn calls.

Concrete feasibility evidence already gathered

  • Local VS Code 1.101.1 and Cursor are available. The local VS Code CLI supports isolated profile paths and the bundled extension host supports an async test runner without a new test framework.
  • The cached vsce 3.9.2 implementation exposes dependency-discovery and issue-linking controls. Its ordinary prepublish and dependency discovery paths invoke npm/yarn, which is why the release design bypasses those paths.
  • A temporary PDFKit bundle outside the repo rendered a valid two-page US Letter PDF with copied runtime data. Poppler extracted the expected title, heading and body. This proves basic bundling feasibility; it does not replace testing the final packaged extension.
  • Three Astra planning reviews and an independent high-reasoning challenge identified generated-table ownership, parser-state reset, UTF-16 offsets and cent-normalization edge cases now included above.
